Forge Session Report

Target: Coin Frontend v0.1 MVP | Date: 30/09/2026

🎯 Core Verdict

Definition Paralysis Broken: Pure Rapid-Capture Ledger for v0.1
Coin v0.1 is not a full budgeting engine yet. Its job is to eliminate spreadsheet friction: private, mobile-first, under 5 seconds to log an expense, with zero third-party tracking. Forward-looking budget calculations (safe daily spend, pay cycles) are strictly deferred to v1.

🔒 Locked Decisions

1. Instant Optimistic Entry under Cold Starts
Mobile entry must never block on Azure Container Apps 5-15s spin-up. Form submits instantly, updating client UI optimistically while TanStack Query retries in the background. Terminal failures show an amber Sync Failed badge and toast retry.
2. Zero-Dependency Client Storage
API key and small un-synced retry queue live in localStorage. IndexedDB is rejected as unnecessary complexity for a payload under 5KB.
3. Monthly Flow Dashboard Scope
Dashboard summary cards strictly display current calendar month flow: Receitas, Despesas, and Balanço do Mês (matches 1:1 with backend GET /api/v1/transactions?year=YYYY&month=MM). Lifetime net worth is deferred.

🚫 Rejected Options & Rationale

Rejected: Forward-Looking Daily Budget in v0.1
Why: Backend currently lacks schemas for target budgets, recurring fixed bills, and pay cycle dates. Forcing it into v0.1 would require wizardry and fake calculations.
Rejected: IndexedDB Offline Sync Architecture
Why: Shares identical browser same-origin security boundary as localStorage; adds async boilerplate and library weight for no functional gain in MVP.
